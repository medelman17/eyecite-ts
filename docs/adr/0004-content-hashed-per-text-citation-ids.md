# Citation ids are content hashes, stable per-text only

A citation id is a branded content hash of (kind | span | matchedText), e.g. `cit_a3f91c2e`. Re-extracting identical text yields identical ids — across runs and across extractor upgrades, so long as the citation's own position and text are unchanged — which is what lets persisted edges re-attach and corpus projections diff cleanly. Two rejections worth remembering: sequential ids (any edit renumbers the tail; the id says nothing verifiable) and span-free hashes with occurrence ordinals (survive unrelated edits, but an inserted duplicate renumbers all later twins — a stability rule too subtle to promise). Consequence, deliberate: editing text upstream of a citation changes its id, and cross-document identity ("Roe is Roe in every opinion") is explicitly out of scope — that is an entity-resolution layer above this library.
